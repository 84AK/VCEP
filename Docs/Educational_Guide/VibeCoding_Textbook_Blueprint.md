# 📚 바이브코딩(Vibe Coding) 교재 및 교육 과정 설계 청사진
> **AI와 함께 생각하고, 기획하고, 세상을 바꾸는 소프트웨어 만들기**
> 
> *본 청사진은 2026년 최신 AI 기술 스택 및 프론트엔드 디자인 트렌드를 기반으로, 바이브코딩을 배우는 학생들과 가르치는 강사/선생님들을 위해 VCEP(VibeCoding Expert Program) 시뮬레이션 플랫폼의 교재화 방향을 정의한 설계 문서입니다.*

---

## 1. 🌟 교육 철학 및 핵심 가치 (Pedagogical Philosophy)

1. **단순 '따라 하기'에서 '주체적 해결'로**
   * 기존 코딩 교육의 문법 암기 및 코드 복사-붙여넣기(Copy-paste) 방식에서 벗어납니다.
   * "스스로 일상의 문제를 정의하고(Planning), AI를 개발 파트너로 부려(Building), 문제를 해결(Solving)해 내는 힘"을 기릅니다.
2. **협업 도구로서의 AI 경험 (AI as a Peer Programmer)**
   * AI를 정답 자판기가 아닌, **함께 일하는 동료(AI 인턴 에이든 등)**로 인식합니다.
   * 불완전한 결과물에 대해 명확한 피드백을 전달하고, 끊임없이 대화하며 결과물을 개선해 나가는 반복적(Iterative) 소통 능력을 학습합니다.
3. **게임화를 통한 심리적 장벽 완화 (Gamification of Learning)**
   * 낯설고 두려운 코딩과 디버깅의 과정을 VCEP의 시뮬레이션 게임(프롬프트 탐정, 스타트업 경영 등)을 통해 친근한 '게임 퀘스트'로 치환합니다.

## 2. 🛠️ 2026 최신 툴체인 및 AI 모델 라인업 (Target Toolchain)

본 교육 과정은 별도의 복잡한 설치 없이 브라우저에서 실행할 수 있는 기초 환경부터, 실제 개발자들이 사용하는 전문가용 에이전트 CLI 환경까지 단계적으로 확장합니다.

| 단계 | 실습 도구 (Tools) | 백엔드 / DB | 추천 AI 모델 (2026년 기준) |
| :--- | :--- | :--- | :--- |
| **기초 (1~3장)** | Gemini Canvas, Google AI Studio, VCEP 웹 시뮬레이터 | Browser LocalStorage | **Gemini 3.5 Flash** (고속 실습), **Claude Haiku 4.5** |
| **중급 (4~5장)** | 단일 HTML 웹앱 제작, VCEP 마스터 앱 연동 | **Google Apps Script(GAS)** + Google Sheets | **Claude Sonnet 4.6** (코드 구조화), **Gemini 3.5 Pro** |
| **심화 (6장~)** | **Antigravity**, **Claude Code** CLI, Git, Vercel | **Supabase** (BaaS) | **Claude Opus 4.8** (자율 에이전트 및 종합 아키텍처) |

## 3. 📅 챕터별 세부 구성안 (Curriculum Structure)

### 🧩 [1부: AI와 첫 소통 시작하기]

#### **Chapter 1: AI의 숨겨진 마음을 읽는 프롬프트 탐정**
* **핵심 질문:** "AI에게 내가 원하는 답을 완벽하게 이끌어내려면 어떻게 말해야 할까?"
* **실습 게임:** `apps/03_expert/prompt_detective.html` (프롬프트 디텍티브)
* **주요 학습 내용:**
  * **프롬프트의 3요소:** 역할(Role), 맥락(Context), 제약조건(Constraints).
  * **시스템 프롬프트(System Prompt) 이해:** AI의 정체성과 행동 강령을 설정하는 방법.
  * **게임 퀘스트 연계:** 탐정이 되어 AI 용의자의 비밀 프롬프트를 추리하고, 원하는 단서를 탈취하는 실습을 통해 자연스럽게 LLM의 프롬프트 처리 구조 습득.
* **👩‍🏫 강사용 티칭 가이드:** "학생들이 규칙을 외우지 않게 하세요. 게임 점수를 높이기 위해 질문을 다듬는 과정 자체가 프롬프트 엔지니어링의 실전 훈련입니다."

#### **Chapter 2: AI 인턴 '에이든'과 협업하는 바이브코딩 시뮬레이션**
* **핵심 질문:** "AI가 엉뚱한 답을 주거나 에러 코드를 줬을 때, 나는 어떻게 대화해야 할까?"
* **실습 게임:** `apps/03_expert/vibecoding_sim.html` (바이브코딩 시뮬레이터)
* **주요 학습 내용:**
  * **반복적 프로프팅(Iterative Prompting):** 피드백을 통해 점진적으로 결과물을 개선해 나가는 순환 주기 학습.
  * **에러와 환각(Hallucination) 대처법:** AI가 뱉은 코드에 오류가 났을 때 당황하지 않고, 에러 로그를 읽고 다시 피드백하는 방법.
  * **역할극 시뮬레이션:** 가상의 AI 인턴 '에이든'의 질문에 건축가/프로젝트 매니저 관점에서 지시를 내려 앱 기획을 완성해 가는 모의 체험.
* **👩‍🏫 강사용 티칭 가이드:** "이 장에서는 코드 작성을 전혀 하지 않습니다. AI와의 소통에서 생기는 마찰(Conflict)을 현명하게 조율하는 법을 배웁니다."

### 🎨 [2부: 내 아이디어를 실제로 만들기]

#### **Chapter 3: 스마트폰 웰니스 메이커 - 내 삶의 문제를 푸는 첫 번째 앱**
* **핵심 질문:** "내가 스마트폰을 너무 많이 쓰는 문제를 앱으로 어떻게 해결할 수 있을까?"
* **실습 도구:** `apps/app_planner.html` ➔ Gemini Canvas
* **핵심 프로젝트:** 스마트폰 오버유즈 개선을 위한 웰니스 앱 (`apps/01_smartphone/` 폴더 기반)
* **주요 학습 내용:**
  * **문제 정의와 기획(PRD 작성):** `app_planner`를 통해 대상 사용자(페르소나) 정의, 필수 기능(Must-Have) 선정 및 와이어프레임 설계.
  * **2026년 디자인 트렌드 적용:** 
    * 정보를 직관적으로 구성하는 **벤토 그리드(Bento Grid)** 배치.
    * 깊이감과 투명감을 더하는 **글래스모피즘(Glassmorphism 2.0)** 스타일링 적용.
    * CSS Container Queries와 CSS Nesting을 사용한 모바일 반응형 웹앱 제작.
  * **localStorage 연동:** 사용자 데이터(스마트폰 잠금 시간, 오프라인 시간 등)를 브라우저에 저장하고 불러오는 데이터 유지 기법.
* **👩‍🏫 강사용 티칭 가이드:** "기획서가 정교할수록 AI가 내뱉는 코드의 퀄리티가 기하급수적으로 올라갑니다. `app_planner`를 활용해 생각의 구조를 설계하는 단계를 충분히 거치게 하세요."

#### **Chapter 4: 마음을 돌보는 멘탈 웰니스 마스터와 컴포넌트 통합**
* **핵심 질문:** "여러 개로 쪼개진 작은 기능의 앱들을 모아 하나의 거대한 서비스 대시보드로 만들려면?"
* **실전 프로젝트:** 감정 다이어리 및 심리 케어 앱 (`apps/02_mental/` 마스터 앱 기반)
* **주요 학습 내용:**
  * **포스트메시지(postMessage API) 통신:** 마스터 대시보드와 하위 미니 앱들이 데이터를 서로 안전하게 주고받는 다중 창 통신 설계.
  * **모듈러(Modular) 디자인:** 재사용 가능한 웹 컴포넌트의 개념 이해.
  * **심미적 완성도 제고:** View Transitions API를 활용해 앱 내에서 페이지나 탭이 전환될 때 네이티브 앱 같은 부드러운 애니메이션 효과 구현.

### 🔌 [3부: 클라우드 연결과 실전 배포]

#### **Chapter 5: 내 앱에 클라우드 날개 달기 (GAS & Sheets)**
* **핵심 질문:** "친구들이 등록한 데이터를 영구적으로 서버에 저장하고, 실시간 통계를 만들 수 있을까?"
* **실전 프로젝트:** Google Apps Script(GAS)를 활용한 실시간 데이터 CRUD (`apps/04_gas_crud/` 기반)
* **주요 학습 내용:**
  * **서버와 데이터베이스의 개념:** 로컬(내 컴퓨터)에 갇힌 데이터와 클라우드 데이터의 차이.
  * **구글 스프레드시트를 DB로 활용하기:** 무료이면서도 직관적인 구글 스프레드시트에 데이터를 읽고 쓰는 **GAS_SERVER_CODE.js** 개발 및 연동.
  * **클라우드 데이터 시각화:** 실시간으로 쌓이는 데이터로 마스터 앱의 통계 대시보드를 갱신하는 연동 원리 습득.

#### **Chapter 6: 터미널 에이전트(Antigravity/Claude Code)와 원클릭 배포**
* **핵심 질문:** "AI 에이전트와 로컬 환경에서 페어 프로그래밍을 진행하고, 내 도메인을 만들어 전 세계에 공유하려면?"
* **실습 도구:** Antigravity / Claude Code CLI, Git, Vercel
* **주요 학습 내용:**
  * **에이전틱 코딩(Agentic Coding) 실습:** CLI 프롬프트를 통해 로컬 파일을 탐색하고 빌드 에러를 자율적으로 찾아서 수정하게 하는 협업 기술.
  * **Git/Github 협업 기초:** 코드 버전 관리와 협업 파이프라인 맛보기.
  * **Vercel을 통한 원클릭 웹 호스팅:** 로컬 프로젝트를 실제 퍼블릭 웹주소로 발행해 나만의 도메인 갖기.

#### **Chapter 7: 몬스터 스타트업 - 코더에서 비즈니스 기획자로**
* **핵심 질문:** "내가 만든 웰니스 앱으로 실제 수익을 올리고 회사를 키운다면 어떻게 해야 할까?"
* **실습 게임:** `apps/03_expert/monster_startup.html` (스타트업 경영 시뮬레이션)

## 👩‍🏫 4. 교사용 티칭 매뉴얼 & 평가 가이드 (Teacher's Manual)

### 1) "에러는 성장을 위한 최고의 기회다" 디버깅 지도 가이드
* **기존 코딩 교사들의 딜레마:** 학생 30명이 동시에 서로 다른 구문 에러(Syntax Error)를 들고 와 질문하면 수업 진행이 마비됩니다.
* **바이브코딩의 대안 - 상담가(Counselor) 대화법:**
  * 학생이 에러를 가져오면 교사가 직접 코드를 고쳐주지 마세요.
  * "콘솔 창에 뜬 에러를 복사해서 **Gemini 3.5 Pro**나 **Claude Sonnet 4.6**에게 **'내가 만든 앱에 이런 에러가 났어. 원인이 무엇이고 어느 줄을 고쳐야 하는지 친절하게 설명해줘'**라고 질문해볼까?"라고 지도하여, 학생 스스로 문제 해결사(Fixer)가 되도록 유도합니다.

### 2) 과정 중심 평가 기준표 (Rubric Example)

| 평가 영역 | 평가 요소 | 상 (Excellent) | 중 (Good) | 하 (Needs Improvement) |
| :--- | :--- | :--- | :--- | :--- |
| **문제 정의 및 기획** | `app_planner` 작성 수준 및 PRD 대조도 | 일상의 구체적 페르소나를 설정하고 핵심 Must-Have 기능을 정교하게 도출함. | 기획의 핵심 내용은 작성했으나, 구체성이 떨어지고 기능 설계가 다소 모호함. | 단순한 한두 줄의 생각 나열에 그쳤으며 기획서 양식을 채우지 못함. |
| **AI 협업 및 프롬프트** | 질문의 정교함 및 피드백 수정 이력 | AI에게 명확한 제약을 주고, 결과물의 에러 발생 시 반복해서 프롬프트를 다듬어 수정함. | AI에게 대략적인 질문만 던져서 코드를 받고, 복사-붙여넣기에 의존함. | AI의 답변을 이해하려는 시도 없이 질문 한 번으로 끝내거나 대화를 포기함. |

| **공학적 해결 및 확장** | 로컬스토리지, GAS 연동 및 버그 극복 | 로컬 저장을 넘어 구글 스프레드시트 클라우드 연동까지 완성하고 발생한 에러를 자율적으로 수정함. | 브라우저 내 로컬 데이터 저장은 구현했으나, 클라우드 연동에서 에러를 극복하지 못함. | 데이터를 전혀 저장하지 못하고 단순 화면 UI 렌더링에만 머무름. |
