# 작업 로그 (2026년 5월 11일) - 픽셀 아트(Pixel Wall) 및 GAS 연동 트러블슈팅

## 1. 개요
- **목표:** Pixel Master Pro (픽셀 아트 앱) 화면에서 그린 그림 데이터를 구글 스프레드시트(GAS 백엔드)와 연동하여 안전하게 클라우드에 저장하고 불러오는 기능 고도화.
- **참여:** 
  - **Relector (작업자):** 프론트엔드 연동 및 UI 코드 수정
  - **Fix (해결자) & Counselor (상담가):** 데이터 연동 에러 원인 분석 및 해결
  - **Doc (서기):** 본 작업 일지 작성

## 2. 발생한 에러 및 문제점
1. **버전 불일치 (Action Mismatch):** 
   - 사용자는 GAS 코드를 최신화(v2.1)했으나, 프론트엔드(`pixel_wall.html`)의 `fetch` 통신 규격이 예전 버전(`action: 'insert' / 'read'`)에 머물러 있어 서로 통신하지 못함.
2. **연결 실패 UI 표시:** 
   - GAS 서버 연결 확인(`testSync()`) 과정에서 브라우저 기본 경고창(Alert)이 반복해서 뜨는 불편함 발생.
3. **가짜 성공 메시지와 엉뚱한 저장소 (Data saved to General):**
   - 픽셀 아트 앱 상단에 엉뚱한(스마트폰 웰니스 앱용) GAS URL이 입력된 상태로 그림 저장이 시도됨.
   - 스마트폰 웰니스 백엔드가 에러 없이 데이터를 받고 `{"status":"success", "message":"Data saved to General"}`을 반환함.
   - 프론트엔드 코드에서는 `includes("성공")`만 체크하다가 영문 `success`도 함께 체크하도록 수정했더니, 에러창 대신 "저장 성공" 토스트 메시지가 뜸.
   - 결과적으로 새 시트의 `PixelData` 탭에는 아무 데이터도 들어가지 않고 스마트폰 시트 `General` 탭에 저장되는 해프닝 발생.
4. **URL 저장 누락 문제:** 
   - 새 GAS URL을 상단 입력창에 넣고 [연결 테스트]는 진행했으나, [URL 저장] 버튼을 누르지 않아 브라우저의 `localStorage`에는 예전 URL이 남아있었음. 그림 저장 시 이 예전 URL로 요청을 보내는 구조적 빈틈 발견.

## 3. 해결 및 구현 내용
1. **통신 규격 최적화:** 
   - `pixel_wall.html`의 모든 통신 액션을 GAS v2.1 규격(`action: 'test'`, `'save'`, `'list'`, `'load'`)에 완벽하게 일치시킴.
   - 데이터는 `JSON.stringify(payloadData)` 형태로 POST 전송.
2. **UX 고도화 (Toast Message):** 
   - 기존의 딱딱한 `alert()` 창을 전부 제거하고, 우측 하단에서 스르륵 나타났다 사라지는 비동기 커스텀 토스트(Toast) 메시지 UI(`showToast()`)를 구현하여 사용자 경험을 대폭 개선.
3. **응답 성공 식별 로직 강화:** 
   - 서버 응답을 확인할 때 한글 "성공"뿐만 아니라 "success"가 포함되어도 정상 저장으로 간주하도록 보완.
4. **자동 URL 저장 시스템 (Human Error 방지):** 
   - 사용자가 새로운 URL을 입력하고 [연결 테스트]에 성공하면, 깜빡하고 [저장]을 누르지 않아도 **자동으로 `localStorage`에 해당 URL을 저장(`localStorage.setItem`)** 하도록 방어 로직을 추가함.

## 4. 향후 참고 사항 (Next Steps)
- 추후 멘탈 웰니스 및 기타 미니 앱들을 통합할 때, 통신 타겟(URL)이 의도한 프로젝트 시트를 정확히 향하고 있는지 검증하는 과정을 추가하면 좋음.
- GAS 백엔드에서 에러 발생 시 `{"status": "error", "message": "상세이유"}`를 명확히 뱉어내게 하여 프론트엔드의 Toast 메시지에 직접 노출시키면 디버깅이 더욱 수월해짐.
