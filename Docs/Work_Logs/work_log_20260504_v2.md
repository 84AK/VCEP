# VCEP 프로젝트 작업 로그 (Work Log - Phase 2)
- **날짜**: 2026년 5월 4일
- **작업자**: Antigravity (건축가/작업자/해결사/서기)

## 1. 작업 개요 (Overview)
`apps/03_expert/prompt_practice.html` (철벽 AI의 마음을 녹여라!) 프로젝트의 미완성 로직을 보강하고, 2026년 최신 웹 트렌드인 **View Transitions API**를 적용하여 사용자 경험(UX)을 극대화함.

## 2. 주요 수정 및 구현 사항 (Implementation Details)

### 2.1 View Transitions API 도입
- **네이티브 화면 전환**: `document.startViewTransition`을 사용하여 캐릭터 선택, 미션 결과 리포트 노출, 스테이지 전환, 엔딩 화면 진입 시 브라우저 레벨의 부드러운 페이드 및 이동 효과를 구현.
- **CSS 최적화**: `::view-transition-old(root)` 및 `::view-transition-new(root)`에 0.5s 애니메이션을 할당하여 자연스러운 연결감을 제공.

### 2.2 캐릭터별 동적 대사 시스템 (Dynamic Dialogue)
- **카일(Kyle) 루트 완성**: 기존에 아이리스(Iris) 위주로 구성되어 있던 스테이지 내레이션 및 미션 피드백 대사를 카일의 성격(원칙주의, 논리 중심)에 맞춰 전면 재작성.
- **캐릭터 이름 UI 추가**: Affection Bar 좌측에 `#char-name` 요소를 추가하여 현재 공략 중인 캐릭터를 명확히 표시.
- **동적 반응 로직**: 
  - Stage 1: 캐릭터별 정체성(RCTF) 수락 대사 차별화.
  - Stage 2: 카일의 경우 '데이터 표본'과 '통계적 유의미함'을 중시하는 피드백 추가.
  - Stage 3: 온도 조절 시 '보안 프로토콜 해제' 등의 캐릭터 특색 대사 삽입.
  - Stage 4: 부정 프롬프트 입력 시 '노이즈 제거' 관점의 사과 수용 로직 적용.

### 2.3 UI/UX 및 버그 수정
- **Affection Bar 리뉴얼**: 레이아웃을 더 세련되게 다듬고 파트너 이름과 호감도 게이지를 효율적으로 배치.
- **엔딩 텍스트 동기화**: 해피/노멀 엔딩 시 캐릭터 이름이 올바르게 출력되도록 템플릿 리터럴 적용.

## 3. 발생한 문제 및 해결 방법 (Troubleshooting)

### 3.1 `#char-name` 참조 오류
- **문제**: JS 코드에서 `char-name`의 `innerText`를 변경하려 했으나 HTML에 해당 ID가 없어 에러 발생.
- **해결**: Affection Bar 내부에 파트너 이름을 표시하는 전용 span 요소를 추가하여 해결.

### 3.2 View Transitions 미지원 브라우저 대응
- **문제**: 구형 브라우저에서 `startViewTransition` 함수 부재 시 스크립트 에러 위험.
- **해결**: `if (document.startViewTransition)` 조건문으로 래핑하여 점진적 향상(Progressive Enhancement) 기법 적용.

## 4. 향후 참고 사항 (Next Steps)
- 현재 2인의 캐릭터만 존재하므로, 향후 '상담가'나 '해결사' 등 새로운 페르소나를 추가할 때 `narrations` 객체에 데이터만 추가하면 즉시 확장이 가능함.
